# engine/: the shared painted-video renderer

This is a p5.js + p5.brush renderer, driven by puppeteer through headless Chrome. It turns a song timeline, chapter files and a message database into a vertical 1080×1920 music video. The house style and hard rules are in [GUIDE.md](GUIDE.md).

## How a project uses the engine (copy-in by script, project overlays on top)

Each project keeps **only its own files** in `projects/<name>/video/build/`. The engine is **copied in** by `engine/sync.mjs`. The build folder's `package.json` runs that copy on `npm install` (`postinstall`), and `npm run sync` re-runs it after you change the engine.

```
projects/<name>/
  data/dms.db                  the message DB (scripts/build_dms.py; never commit a real one)
  video/
    song_cut.wav lyrics.txt beats.json aligned.json chapters.json
    build/
      package.json             deps + "postinstall": "node ../../../../engine/sync.mjs ."
      .gitignore               ignores everything sync copies in, plus node_modules/ out/ previews/
      src/timeline_data.js     TL = {duration, bpm, beats, lines, out?, audio?}   (scripts/make_timeline.py or your own)
      src/story.js             HUD.birthday, HUD.label, storyKeys([...])        (the director's file)
      src/cast_project.js      project cast: re-skins, per-age looks, outfits, extra people (optional)
      src/props_project.js     project sets and props (optional)
      src/hud.js               project HUD tweaks (optional)
      src/msg_data.js          per-day sent counts for the odometer              (node tools/msgcounts.mjs)
      src/ch/*.js              one file per chapter, loaded in name order
      src/lab/p_*.js           project test benches (optional)
      assets/*.png             riso photo prints (tools/print_photo.py)
      STORYBOARD.md            the project header (song, BPM, story, audience, tone) + the shot list
      ── copied in by sync ──  render.mjs studio.html GUIDE.md src/{core,frame,cast,props}.js src/lab/ tools/ assets/fonts/
      ── generated ──          src/project_files.js (tools/assets.mjs), .engine-sync.json (sync.mjs)
```

**Engine-owned vs project-owned.** Never edit the copied engine files inside `build/`. Per-project changes go in the project-owned overlays, which `studio.html` loads after `core.js`, `frame.js`, `cast.js` and `props.js` and before the chapters, in this order: `msg_data.js`, `cast_project.js`, `props_project.js`, `hud.js`, `story.js`, `ch/*.js`. Everything in the engine is a global, so an overlay can extend it:

- `src/cast_project.js`: `Object.assign(CAST.CHAR.me, {...})` re-skins a role, `CAST.ME_AGE[n]` / `CAST.SIBLING_AGE[n]` tune per-age looks, `CAST.OUT.<role>.<key> = {...}` adds an outfit, and `CAST.CHAR.x` + `CAST.OUT.x` + `window.x = (x, y, u, o) => castMember('x', x, y, u, o)` adds a person. See the MINI MANUAL at the top of `src/cast.js`.
- `src/props_project.js`: new set and prop functions (reuse `paint`, `scribble`, `halo`, `SETS.*`, `PROPS.*`), or wrappers around engine ones.
- `src/hud.js`: set `HUD.*`, or replace a HUD function by assignment (`drawMeter = function (c, t) {...}`); see the comments above `STORY_DATES` in `src/frame.js`.
- `src/story.js`: `storyKeys([[t, 'YYYY-MM-DD', 'H:MM AM', {label, roll, age}], ...])` and `HUD.birthday`. The first `storyKeys()` call replaces the engine's placeholder date.

**Sync never loses work.** `sync.mjs` records the hash of every file it copies in `build/.engine-sync.json`. If an engine copy was edited inside `build/` since the last sync, the next sync leaves it alone and names it in a warning. `node <path>/engine/sync.mjs . --force` replaces it after saving the edited copy in `build/.engine-sync-backup/<time>/`. (A build synced before the manifest existed gets that backup for every differing file, and is then updated.)

**`src/project_files.js`** is generated by `tools/assets.mjs`. It lists `assets/` and the project scripts above, so you never edit `studio.html` per project. `sync.mjs`, `render.mjs` and `bin/t2mv timeline` run it; run `node tools/assets.mjs` yourself after adding a new project file, before you open `studio.html`.

Why copy instead of linking to `../../engine`? `studio.html` loads plain `<script>` files and `node_modules/` relative to itself. A self-contained `build/` therefore opens directly in Chrome and renders with the same relative paths that agents use. Always change engine files in `engine/`, then run `npm run sync`.

## Files
| File | What it is |
|---|---|
| `src/core.js` | paper, paint, lettering, receipts, camera, timing (`beatT`, `wordT`, …) |
| `src/frame.js` | chapter registry, karaoke strip, story-date stamp, MSGS SENT odometer, compositing, render hooks, `HUD`, `storyKeys()` |
| `src/cast.js` | generic cast: `me` (ages 12–19+), `mom`, `dad`, `sibling`, `friendA…H`, `cofounder`, `coworker`, `grandpa`, `partner`, `kid`, plus `crew()`, `move()`, `mood()`, `tiny()` |
| `src/props.js` | generic sets (`homeRoomSet`, `kitchenSet`, `dormSet`, `apartmentSet`, `gymSet`, `cityNightSet`, …) and props (`phone`, `laptop`, `car`, …) |
| `src/lab/*.js` | test benches (`--lab=name`) |
| `render.mjs` | `--sheet`, `--stills`, `--clip`, `--frames`, `--encode`, `--lab`. Takes the duration, output name and audio from `TL` or from the `--out=` / `--audio=` flags. Point `--chrome=` or `$T2MV_CHROME` at Chrome. |
| `tools/checkquotes.mjs` | verifies every `receipt()` against the DB. Finds the DB from `--db=`, then `$T2MV_DB`, then the nearest `data/dms.db` walking up from the current folder. |
| `tools/msgcounts.mjs` | DB → `src/msg_data.js` |
| `tools/chat_photos.py`, `print_photo.py`, `halftone.py` | export photos from Messages and make riso halftone prints |
| `sync.mjs` | copies the engine into a build folder (protects copies edited there; `--force` to replace), then runs `tools/assets.mjs` |

## Quick start (the demo)
```
cd projects/demo/video/build
npm install                                   # installs p5 / p5.brush / puppeteer-core and syncs the engine in
node tools/checkquotes.mjs                    # prints only OK
node render.mjs --frames=0:30 --workers=4
node render.mjs --encode --out=out/demo.mp4
```
This needs Node 22, ffmpeg, sqlite3 and Google Chrome (macOS: `/Applications/Google Chrome.app`).
